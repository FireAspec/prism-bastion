# Призменный карьер / prism-quarry

Карта 13 кампании, геометрическая группа 3, тема `foundry`, рекомендована сложность `hard`. Мир — 1280 × 720. Цель сюжета — вернуть ядро большого маяка. После первого стандартного прохождения кампанийный модуль открывает башню `prism` (она **не входит** в исходный набор до победы).

## Игровая геометрия

| Параметр | Северная / длинная | Южная / короткая |
|---|---|---|
| Вход | (32, 170) | (32, 548) |
| Выход | (1246, 283) | (1246, 469) |
| Длина осевой линии | 1657.75 px | 1305.49 px |
| Время при 132 px/с без контроля | 12.56 с | 9.89 с |
| Базовая тактика | Контроль больших связок на разворотах, артиллерия | Ранний огонь и отдельный резерв против быстрых целей |

Оба маршрута шириной 44 px, не пересекаются с запретами и водой. Координаты всех сегментов и полигонов хранятся в `src/content/maps/prism-quarry.ts`, не копируются отдельно в рантайм. Концы выделены разными воротами в правой части фонового SVG; это действительно два отдельных выхода.

Семь явно заблокированных ландшафтных островов — каркасы подъёмников, дробильные станции, склад и скальный выступ. Единственный технологический бассейн расположен внизу между x=702..889, y=597..694, с позицией (798,649) радиусом 30 под будущую водную башню. Он не требуется для первого прохождения: на суше сохранены позиции для всех открытых боевых технологий.

Footprint проверен целиком, с запасом 2 px относительно пути, воды, препятствий и границы карты. Все 10 сухих центров служат запасными точками и не являются скрытыми бонусами или дополнительными категориями местности в контракте.

## График прибытия

В `waveOverrides` заданы 36 расписаний: 1–9, 11–13, 15, 17, 19, 21, 24, 27, 33, 37, 41, 44, 49, 53, 57, 61, 64, 68, 72, 77, 81, 85, 89, 93, 97, 99. В этих раундах северная группа приходит с 1-й секунды, южная с 7–12-й; `preview` отдельно показывает численность, время первой цели и интервал для каждой линии. Самые ранние волны обучают распределению обороны. Редкие элитные и быстрые южные группы создают риск без скрытой смены маршрута.

Боссовые раунды 10/20/40/60/80/100 и все остальные волны берутся из общего генератора. `waveOverrides` не меняют `reward` и не выдают деньги повторно. Текущий контракт не содержит отдельного поля для расписания каждой произвольной волны: непрописанные раунды наследуют `WaveDef.preview`, а центр интеграции должен проверить их lane/preview. Сложность геометрии **не** задаёт количество волн; соответствующие префиксы общего набора — easy 40, normal 60, hard 80, extreme 100.

## Первый доступный арсенал

`needle`, `cannon`, `frost`, `beacon`, `scatter`, `ember`, `saw`, `venom`, `rail`, `tesla`, `mortar`, `observatory`, `mint`, `orchard`, `drone`, `rocket`, `resonator`, `forge`, `harbor`, `tide`, `coral`, `chrono`, `gravity`. **Без `prism`** (награды самой карты), `mirror`, `mine` и технологий следующих сюжетных узлов. Планы не предполагают навыков метапрогресса. `iron-oath` дополнительно блокирует знания, продажу и пассивный доход.

## Передаваемые кандидаты стратегий (не подтверждённые победы)

Исполняемые действия находятся в `validation/maps/prism-quarry/replay.ts`: точные wave/tick, место, tower ID, branch index, targeting и неизменяемый seed. Tick=0 означает фазу постройки перед соответствующей волной (wave=0 — перед первой). Нумерация веток A/B/C — 0/1/2. Все кандидаты играют hard, 80 волн, без знаний и с легально доступным начальным набором.

### Бюджетный контроль

При hard базовые цены tower ×1.1, начальные деньги 850; half-cash получает 425. Функция `placementBudgetFloor` рассчитывает гарантированный нижний предел средств **только из стартового бюджета и завершённых наград за раунды** и вычитает перечисленные базовые tower-покупки. Он не учитывает поп-кэш, бонусы, фермы, а также **затраты на улучшения**, поэтому проверка не доказывает доступность полного плана. Для покупок tower нижняя оценка не опускается ниже нуля. Реальный `executeReplay` списывает все фактические цены через engine и прекращает сценарий при первой ошибке.

## Проверка, интеграция и ограничения

Локальные команды (из корня проекта):

```sh
npm ci
npm run typecheck
npm test -- --run tests/maps/prism-quarry.test.ts
node --import tsx --input-type=module -e "import {analyzeMap} from './validation/maps/prism-quarry/geometry.ts'; console.log(analyzeMap())"
node validation/maps/prism-quarry/render-preview.mjs
npm run check
```

`render-preview.mjs` делает PNG при наличии установленного Chromium Playwright; векторные фоны можно отдельно открыть в Inkscape при 1366×768. UI рендерит полилинии из `MapDef` поверх фонового SVG: фон не содержит игровых дорог и не создаёт дублированный коллайдер. Миниатюра — самостоятельный SVG.

### Фактически выполненная проверка модуля

- `npm run check`: успешен. TypeScript strict без ошибок, все **16 тестов / 4 файла** прошли, Vite production build завершён.
- `tests/maps/prism-quarry.test.ts`: 7/7. Проверяет реальные полигоны, две полилинии, независимые выборки по сегментам, окружности footprints, расписание, заблокированные технологии и три формально корректных кандидата replay.
- `analyzeMap()`: `errors=[]`; 18 сегментов, 8 полигонов, 11 площадок, 4 центра в радиусе 160 px от обеих дорог.
- Фон и отдельная миниатюра **отрендерены и просмотрены** при 1366×768. Исправлен неподдерживаемый Inkscape-фильтр, который скрывал декоративные группы и название миниатюры.
- Дополнительный `validation/maps/prism-quarry/scene-1366x768.png` создан из фонового SVG и геометрической накладки на оба маршрута. Это статическая композиция для QA, **не** реальный gameplay screenshot и не браузерный снимок `preview.html`.
- Попытка реального headless HTML-предпросмотра с Playwright остановилась из-за отсутствующего Chromium. Загрузка Chromium через Playwright была предпринята отдельно, но CDN вернул повреждённый/пустой ZIP; браузерный рендер интерактивности остаётся непроверенным.

`executeReplay(plan, createEngine)` принимает фабрику настоящего `GameEngine` и возвращает только наблюдённые победу/поражение, итоговые жизни, кредиты, волну, число исполненных действий и отказ, если он возник. Список `REPLAY_PLANS` имеет явный статус `unverified`. До реализации `src/engine`, `src/content/waves` и башен нельзя честно утверждать проходимость карт или режимов. После интеграции центральная балансировочная проверка должна воспроизвести все три плана, обнаружить отказы покупок/нехватку DPS, исправить порядок действий и сохранить подтверждённые результаты отдельно.

Ограничения контракта: нет отдельных MapDef-тегов специальных площадок, временных порталов или пользовательских правил смерти; поэтому они не выдуманы локально. Позиции и их роли зафиксированы только в validation/docs. Плавающие ресурсы и звуки не включены: карта использует штатные звуки foundry и стандартный визуальный renderer.
