# Карта 12 — «Павшая обсерватория»

## Игровая идея

`fallen-observatory`, сюжетная позиция 12, геометрическая сложность 3/4, тема `garden`, рекомендуемая сложность `hard` (80 волн). В мире 1280×720 лежит разрушенный телескоп с гравитационной линзой. Цель — удержать путь среди крупных видимых обломков и поднять линзу после победы. Награда кампании — `gravity`, **недоступная на первом прохождении самой карты**. Другие последующие технологии также заблокированы. Разрешённые в первом забеге 22 башни заданы константой `FIRST_VISIT_TOWERS` в replay fixture; в ней нет `gravity`.

## Геометрия и графика

- Одна полилиния: `(0,170) → (335,170) → (408,248) → (785,248) → (862,390) → (1280,390)`.
- Ширина 54 px; длина 1398.36 px. Три главные прямые — 335/377/418 px; нет нулевых сегментов, вход и выход видны на краях.
- Шесть непроходимых полигонов: два западных обломка, северная телескопная площадка, южное оррери, северный купол, юго-восточная колоннада. Их **точные контуры** в SVG совпадают с `MapDef.blocked`.
- Три водоёма с сухими подходами — западный, южный центральный и узкий северо-восточный резерв для будущих водных башен.
- Фон — самостоятельный векторный `background.svg` 1280×720, миниатюра — отдельный `thumbnail.svg` 640×360. Фон **не рисует путь поверх игрового canvas**, поэтому не спорит с отрисовщиком. `preview.html` содержит свой отключаемый QA-слой дороги/строительства/препятствий.
- Оценка времени без бонусов: `scarlet` 26.9 с при 52 px/s, `lemon` 12.2 с при 115 px/s, `dart` 10.6 с при 132 px/s, `boss-chrono` 77.7 с при 18 px/s. Это длина/скорость, а не боевое доказательство.

## Кандидаты композиций, без претензии на победу

Все сценарии используют `hard`, фиксированный seed, одиночного игрока, пустые знания, только ранее открытые технологии. Полный перечень волн, тиков, позиций, покупок, улучшений и режимов находится в `validation/maps/fallen-observatory/replays.ts`. Тик 0 означает строительную фазу **до** названной волны.

1. **standard-crossfire:** A/B на первой волне за 275+468=743, C с 5-й, F мороз с 13-й, E мортира с 20-й, D рельсотрон с 28-й, G/H щиты и ракеты после 37/43-й. Состав опирается на пересекающийся огонь и закрывает вход и последний поворот. Против невидимых — обнаружение, против брони — бронепробитие, против толпы — мортира, против босса — приоритет сильной цели.
2. **half-cash-needles:** один `needle` на старте (275 из 425), второй к 6-й, затем `scatter` на 17-й и `frost` на 25-й; тяжёлые покупки отложены. Риск — ранний дефицит DPS и очень позднее обнаружение/противобоссовое усиление. Доход от экономики не предполагается.
3. **iron-oath-lockdown:** первая пара A/B за 743 из 850, постепенные `frost`, `mortar`, `rail`, `tesla`, `rocket`, резерв I/J. Нет знаний, ферм, продажи или дополнительного дохода. Одна утечка означает поражение; требует точной настройки контроля.

`basePurchaseLedger()` считает нижнюю границу денег после **базовых размещений** из стартовых средств и формулы hard-волны `60+3n`; для half-cash использована половина суммарной награды с учётом дробного остатка. **Доход за снятые слои, стоимость улучшений, погодные модификаторы и реальные боевые затраты не подтверждены.** Поэтому положительный остаток в этом ledger не доказывает доступность всех upgrades, а статический DPS не доказывает проходимость.

## Воспроизводимые проверки

```bash
node validation/maps/fallen-observatory/smoke.mjs
npx tsx validation/maps/fallen-observatory/validate.ts
npx tsx validation/maps/fallen-observatory/replays.ts
npx tsx validation/maps/fallen-observatory/replays.ts --run
npm run check
```

Первый сценарий работает без сторонних зависимостей на Node 22+ и непосредственно анализирует TS-геометрию с ограниченным VM, а не её вручную переписанную копию. Последний replay использует настоящий `createGame`, `createCombat`, `loadContent`, пошаговые тики 1/60 с и отвергает отрицательные результаты команд, некупленные улучшения, преждевременную победу, поражение и зависание. В базовом commit движок/волны всё ещё заглушки, поэтому **все три сценария имеют исходный статус `unverified`**. Финальный результат должен быть записан только после реальной симуляции; автоматический runner не заменяет победу статической оценкой.

## Интеграционные вопросы

- Общая волновая программа ещё не реализована. На волнах 41–59 планируются многополосные группы, а эта карта имеет только lane 0. В `waveOverrides` пока `{}`: после появления реальных определений волн нужен явный map-specific перевод групп на lane 0 **без потери врагов, боссов и выплат**, либо единая легальная курируемая вариация для однополосных карт. Нельзя скрыто переносить врага с несуществующей полосы в runtime.
- Нельзя требовать `gravity` как контрприём до первого завершения №12. Надо проверить в общей балансовой симуляции `standard`, `half-cash`, `iron-oath` на раннем легальном профиле.
- Визуальный обзор предназначен для 1366×768 через `public/art/maps/fallen-observatory/preview.html`; слой запрещённых площадок включается кнопкой «Запреты». SVG остаётся вектором для 4K. Нужны фактический снимок UI и интеграционная проверка renderer при появлении возможности запуска графической оболочки.
