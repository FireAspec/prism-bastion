# Карта 14 — «Зеркальные террасы»

**ID:** `mirror-terrace` · **сюжет:** 14/20 · **группа геометрии:** 3/4 · **тема:** `garden` · **рекомендация:** `hard`.

## Суть и границы данных

Три открытых яруса сада: верхний (0–250), средний (250–500), нижний (500–720). Две независимые полилинии входят слева и выходят справа. Маршрут A выходит около (1280,526), маршрут Б — (1280,192). Пересечение — ровно (650,360), без общих отрезков, с шириной дорожки 44. При попадании в пересечение один экземпляр врага должен оставаться **одним ID на своей полосе**; MapDef не создаёт новый объект при пересечении. Сам факт отсутствия двойного урона должен быть отдельно доказан в combat/engine: прицельный снаряд и AoE учитывают ID цели, а не количество линий, геометрически содержащих точку.

- Длина A ≈ 1582.57 px, длина Б ≈ 1588.70 px.
- Базовый максимальный из указанных обычных противников темп 132 px/с (dart): ≈ 11.99 и 12.04 с от входа до выхода. При overdrive ×1.35 ориентир ≈ 8.88 и 8.92 с; это **геометрическая оценка**, не проигранная волна.
- Босс со скоростью 17 px/с проходит примерно 93 с, до внешних модификаторов и контроля.
- `pathWidth=44` — не footprint. Радиус 40 для наземных и 24 для водных площадок принят как консервативный тестовый диск; конкретный `TowerDef.footprint` дополнительно проверяет движок.
- Вода — отдельный слой `water` (не продублирована в `blocked`); две полноценные водные площадки доступны при повторном прохождении.
- Заграждения перечислены полигонами в `blocked`: северная разбитая мастерская, стела, восточная линза и два нижних постамента. Рендер должен подсветить недопустимую постановку.
- Фон содержит **рельеф, пруды и построения**, но не дублирует игровые дороги; поверх него дорожки рисует Canvas-рендерер. `preview.html` отдельно показывает тестовое наложение обеих линий.
- `waveOverrides={}`: используется единая программа волн, пока соседний модуль реализуется. В задании нет угрозы, требующей `mirror` до победы; если центральный баланс обнаружит такую зависимость, понадобится явная локальная группа и повторные replay.

Сюжет: собрать разрушенную зеркальную мастерскую. Награда **`mirror` только после стандартной победы**, никогда в исходном наборе первого захода. Разблокировку выполняет владелец кампании; MapDef хранит только карту и описание.

## Три кандидата replay, ещё не доказанные

**Все три имеют статус `unverified`.** Полные машиночитаемые списки `wave,tick,site,tower,path` и исполняемый `runCandidateReplay` — в `validation/maps/mirror-terrace/replays.ts`. Тик 0 означает действие в фазе строительства перед этой волной; `path=0/1/2` соответствует A/B/C. Исполнитель не подбрасывает деньги: на отказ `dispatch`, превышение таймаута и преждевременное завершение волны он возвращает ошибку. Для честной верификации нужны настоящие `loadContent()`, `createGame()`, `createCombat()` и игровая экономика.

Начальные покупки используют `ceil(cost × 1.10)`: needle 275; scatter 468. Награда hard за завершённый раунд n: `60+3n`, в half-cash — половина (учёт дробного остатка ведёт симуляция). Это только формулы гарантированных волн при их успешном завершении; доход за снятые слои, цены улучшений и фактическая способность выжить **не подтверждены**.

## Проверки и интеграционный контракт

Изолированная команда после установки зависимостей:

```sh
npm ci
npx tsx validation/maps/mirror-terrace/geometry.ts
npx vitest run tests/maps/mirror-terrace.test.ts
npm run check
```

В средах, где `tsx` не может создать IPC-сокет, геометрию можно запускать без него: `node --import tsx validation/maps/mirror-terrace/geometry.ts`.

Контрольная проверка 23.10.2026 на изолированной ветке: `npm run check` завершился успешно (15 тестов), изолированный набор карты — 6 тестов; отчёт геометрии `ok=true`, ошибок нет, одно пересечение `(650,360)`, 8 сухих и 2 водные площадки. Оба SVG отрисованы в Inkscape, фон проверен в размере 1366×768 вместе с наложением маршрутов; для повторных элементов использованы совместимые `xlink:href`. Реальные боевые replay остаются `unverified` из-за отсутствующих в базовом коммите движка и контента.

`geometry.ts` выводит JSON с `ok/errors`, длинами, одним пересечением, ETA и числом валидных площадок. Тесты проверяют копирование данных, точное совпадение preview-полилиний, конфигурацию первой кампании, бюджет входа и честные статусы fixture. Для визуальной QA открыть `public/art/maps/mirror-terrace/preview.html` локально в окне 1366×768; отдельно открыть SVG-файлы на этом же размере. Ограничить или отключить motion можно обычным UI приложения, сам фон статичен.

После интеграции:

1. Прогнать каждый из трёх кандидатов через `runCandidateReplay(config, plan)`. Измерить реальный `finalLives`, `finalCredits`, wave, расход и `status`. Непрошедший кандидат не объявлять решением.
2. В настоящем `GameEngine` проверить коллизии каждой `TowerDef.footprint` у всех сайтов, включая размещение рядом с пересечением и занятыми башнями.
3. Проверить ровно один экземпляр enemy ID и один hit event при прохождении (650,360), даже если попадание AoE охватывает обе полосы.
4. Проверить с видимыми предупреждениями босса (волны 10/20/40/60/80), раскрытием cloak и корректным распределением wave override/награды в hard.
5. Повторить half-cash и iron-oath без постоянных бонусов, сохранений, дохода извне или скрытого открытия mirror.
6. При признаках зависимости от пока закрытой технологии добавить **явный** `MapDef.waveOverrides` для конкретной группы и повторить все три стратегии.

Изолированная геометрия не может доказать боевую проходимость. Модуль не меняет общие контракты, генератор каталога, команды, награды, формулу урона и соседние модули.
