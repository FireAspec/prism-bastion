# Карта 20 — Сердце бури (`heart-of-storm`)

## Назначение

Финальная оборона эстуария: четыре постоянных шлюза сходятся в общий перешеек и
расходятся к двум обозначенным маякам. Задача кампании — синхронизировать сеть маяков;
за первое прохождение выдаётся финальная **косметическая медаль**, а не новая башня.

- Контракт `MapDef` v1; размер поля **1280×720**, `pathWidth=38`.
- Геометрическая группа **4/4**, `campaignIndex=20`, `theme=estuary`, рекомендуемый
  забег `extreme`. Геометрическая группа не меняет число волн. Выбранная сложность
  по общей программе задаёт **40/60/80/100**.
- Стартовый пул: `needle, cannon, frost, beacon, scatter, ember, saw, venom,
  rail, tesla, mortar, observatory, mint, orchard, drone, rocket, resonator,
  forge, harbor, tide, coral, chrono, gravity, prism, mirror, mine, portal,
  bank, storm, bastion`. Пул перечислен как точный набор `unlockedTowers` во всех
  replay-сценариях. Медаль финала не открывается до победы.
- 4 полилинии: входы `(0,104)`, `(0,266)`, `(0,464)`, `(0,624)`;
  выходы — `(1280,211)` для северной пары и `(1280,510)` для южной пары.
  Маршруты и точки назначения показаны до старта волны, не меняются на ходу.
- Общий ствол `(656,354) → (744,354) → (825,301) → (934,301) →
  (1022,353) → (1084,353)` имеет **458,01 px** длины. Даже при скорости
  132 px/с это **3,47 с** до развилки, плюс дорога к видимому выходу.
  Это только оценка движения без статусов и боевого замедления, не симуляция.

## Тактическая геометрия

Длина линий по измерению: 1467,39 / 1405,69 / 1396,39 / 1480,70 px.
Восемь узлов внутреннего периметра и ещё два резерва занимают сухую землю,
проверенную для кругового footprint радиусом **28–30 px** с запасом **2 px**.
Два водных сокета полностью находятся в полигоне воды и видят путь с дальности
170 px: у северной воронки `(913,175)`, у южного фарватера `(610,570)`.

Точные координаты, тип размещения и рабочие радиусы хранятся в
`validation/maps/heart-of-storm/sites.json`. Полигоны воды и запретных
руин хранятся непосредственно в `getMap()` и отрисованы в фоне. **На них нельзя
размещать наземные башни**, но не существует участка, где водная башня обязательна:
сухие площадки доступны у обеих подходящих ветвей и общего участка. Проверка
ориентируется на полный круг footprint, а не только центр. Если конкретная
башня имеет больший радиус, движок должен отвергнуть посадку, а игрок выбрать
соседнюю площадку — данные не разрешают строить поверх запретных зон.

Две принципиально разные композиции:

1. **Общий перешеек** — `north-socket`, `south-socket`, `storm-eye`,
   `return-ramp`: массовый урон по слиянию и контроль до развилки; сухие
   `north-approach` / `south-approach` страхуют ранние входы.
2. **Два маяка** — `return-ramp`, `south-battery`, `fork-guard`,
   `north-lantern`, `south-lantern`: резерв и обнаружение у развилки, отдельно
   защищённые выходы; `deep-channel` даёт водный вариант.

Предпросмотр `public/art/maps/heart-of-storm/preview.html` работает без сети:
выбор волны подсвечивает объявленные входы; переключатели позволяют сравнить
обе композиции и три режима. `background.svg` предназначен для игрового поля:
он содержит только территорию, воду и декорации, **без встроенных полос пути**,
которые рисует renderer. `thumbnail.svg` — отдельная композиция с читаемыми
линиями, двумя выходами и названием, не уменьшенная копия фона.

## Волны и справедливость

`waveOverrides` перечисляет **1..100**. Для обычных волн главная группа
входит по шлюзам `0→1→2→3` циклически; начиная с 13-й некоторые волны
получают вторую заранее объявленную группу. У боссов вход прописан явно:

| Волна | Босс | Вход | Выход |
|---:|---|---:|---|
| 10 | boss-carapace | 0 | северный |
| 20 | boss-brood | 3 | южный |
| 40 | boss-mirror | 2 | северный |
| 60 | boss-chrono | 1 | южный |
| 80 | boss-tempest | 0 | северный |
| 100 | boss-eclipse | 3 | южный |

Босс и свита проходят по геометрическим линиям до одного из видимых маяков.
Все `at`, `every`, `lane`, `enemy` и `count` закреплены в данных без RNG и
переключения посреди волны. Превью показывает **все** активные группы.
Номера боссов и их `boss`-идентификаторы согласованы с общим контрактом.
`reward` не переопределяется — боевые кредиты за волну выдаёт движок один раз.

Эти явные составы обеспечивают разнообразие входов даже до готовности общей
программы волн. **Они не прошли балансировку реальным combat engine**;
количество и интервалы — исходные кандидаты. После интеграции центральный
валидатор обязан проверить скорость, доход, угрозы, боссы и доступность
контрприёмов из 30 уже открытых башен. Нельзя называть их доказанно
проходимыми только по геометрии и отсутствию закрытых технологий.

## Replay-кандидаты (неверифицированы)

Машинно читаемые сценарии: `validation/maps/heart-of-storm/replays.json`.
Каждая запись содержит `seed`, режим, выбор `extreme`, доступный пул технологий,
волну, **тик относительно начала волны**, действие, tower ID или ref,
место покупки. `tick=0` означает фазу строительства перед запуском указанной
волны. Все покупные команды проходят через `dispatch`, который обязан
проверить деньги; отрицательные бюджеты и «бесплатные» башни не допускаются.
Два стартовых игломёта на extreme стоят по 300 кредитов
(`ceil(250 × 1,20)`), половинный старт в half-cash — 425 кредитов.

| Режим | Начало | Стартовые покупки | Остаток |
|---|---:|---|---:|
| `standard` | 850 | 2× needle: north-socket, south-socket | 250 |
| `half-cash` | 425 | 1× needle: storm-eye | 125 |
| `iron-oath` | 850 | 2× needle: north-socket, south-socket | 250 |

## Проверки и запускаемые инструменты

Из корня репозитория:

```sh
node --import tsx validation/maps/heart-of-storm/geometry.ts
npm test -- tests/maps/heart-of-storm.test.ts
npm run check
node --import tsx validation/maps/heart-of-storm/replay.ts all
```

Геометрический анализатор вычисляет точное пересечение сегментов и минимальное
расстояние до каждого полигона, включая весь радиус footprint. JSON-отчёт
содержит границы, длины линий, общий участок, площадки, клиренсы и ошибки.
Vitest дополнительно сверяет маршрутное JSON-представление preview с `MapDef`,
корректность боссовых групп, набор технологий и бюджеты открывающих покупок.

Replay runner исполняет команды в указанном тике, смотрит на состояние
движка после каждого тика, запрещает отрицательные кредиты, записывает
фактические траты, жизни и деньги. **Код возврата 2 и JSON `unverified`** —
ожидаемое текущее состояние, когда `loadContent` и combat пока ещё заглушки.
После интеграции возвращаются `verified` только при реальной победе на 100-й
волне либо `failed` с причиной. Начальные поля `actualFinalLives`/
`actualFinalCredits` в файле намеренно `null`; итоговые значения определяются
только настоящей симуляцией.

Область статических проверок не включает реальный DPS, финальный доход,
стоимость T1 по недостающему каталогу, законность покупок на поздних волнах,
боссовые фазы и возможность победы в трёх режимах. Эти пункты остаются
**непроверенными**, пока не появятся остальные игровые модули.
