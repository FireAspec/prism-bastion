# «Садовая стена» — карта 05

## Назначение

`orchard-wall`: группа геометрической сложности **1**, сюжетный узел **5**, тема **garden**, рекомендуемая сложность **easy**. Цель эпизода — открыть торговый квартал. Сюжетная награда **после первой победы**: `mint` и `orchard`. Они не входят в исходно открытый состав; выдача награды принадлежит `CampaignNode`, а не `MapDef`.

При первом достижении доступны только: `needle`, `cannon`, `frost`, `beacon`, `scatter`, `ember`, `saw`, `venom`, `rail`, `tesla`, `mortar`, `observatory`. Ни `mint`, ни `orchard`, ни поздние технологии в сценариях не используются. `difficulty:1` не меняет число волн: выбранный difficulty определяет 40/60/80/100 (easy/normal/hard/extreme).

## Геометрия и эстетика

- Мир **1280 × 720**; один последовательный путь длиной около **3433 px** и шириной **42 px**.
- Видимый янтарный вход на левой кромке **(0, 206)**; голубой выход на правой **(1280, 355)**.
- Западная и восточная петли охватывают две садовые клумбы; центральный проход допускает общий перекрёстный обстрел.
- Намеренные пересечения сегментов **6/13** и **19/26** обозначены мостками на `preview.html`. Это одна линия, не две ветки и не двойной урон: прогресс врага всегда по дуговой длине.
- Северная ограда, пять строений/садовых клумб имеют явные `blocked` полигоны. Декоративные травы и цветы не создают невидимых запретов.
- Южный пруд — единый `water` полигон с берегом у y≈604–625; к будущим водным башням доступ сохраняется, но начальные башни размещаются на сухих позициях.
- `background.svg` не содержит дублирующего дорожного слоя, врагов, башен или интерфейса. Игровой renderer должен нарисовать дорогу по контрактной полилинии поверх фона. В `thumbnail.svg` маршрут намеренно показан для меню.
- Тема: глубокая сине-зелёная земля, медная/янтарная подсветка входа, известняковая стена, плодовые деревья, холодная лазурь пруда и выхода.

## Replay-кандидаты (неподтверждённые)

`validation/maps/orchard-wall/replay-candidates.json` содержит полный machine-readable список событий по трём сценариям. Каждое действие имеет **волну, тик, позицию, покупку/ветку**, собственный seed и символический ID башни. `tick:0` означает действие **в фазе строительства непосредственно перед стартом данной волны**. Реальный runner узнаёт ID постройки из `CommandResult`/снимка, не угадывает их. Любой отказ при покупке, поражение или таймаут делает проверку неуспешной.

### Денежные ограничения

Ниже — гарантированный **входящий поток**, если волны уже завершены, без денег за снятые слои и **до вычета покупок**. Это не подтверждённые остатки кассы и не доказательство доступности покупки.

| Easy режим | Старт | Награды за 1…10 / 1…20 / 1…40 | Старт + награды после 10 / 20 / 40 |
|---|---:|---:|---:|
| standard | 1000 | 1275 / 3050 / 8100 | 2275 / 4050 / 9100 |
| half-cash | 500 | 637 / 1525 / 4050 | 1137 / 2025 / 4550 |
| iron-oath | 1000 | 1275 / 3050 / 8100 | 2275 / 4050 / 9100 |

Формула для easy: `100*n + 5*n*(n+1)/2`; half-cash сохраняет дробные части в сотых. В base отсутствуют цены башен и полная таблица волн: фактический остаток и проходимость нельзя честно посчитать заранее. `waveOverrides={}`; лишь после интеграции при выявлении закрытого обязательного контрприёма следует добавить конкретную замену, не добавляя двойную награду.

## Автономная приёмка и будущая интеграция

```bash
npm ci
npm run check
npx tsx validation/maps/orchard-wall/geometry-check.ts
npx tsx validation/maps/orchard-wall/run-replays.ts --validate
npx tsx validation/maps/orchard-wall/run-replays.ts --run
```

- Анализатор возвращает JSON: `valid`, перечень ошибок, длину, пересечения, `roadMargin` и `blockedMargin` каждого слота; код 1 при ошибке.
- `--validate` проверяет время, режимы, доступность состава, легальность веток, столкновения footprint и минимальную бюджетную арифметику, но возвращает **unverified**.
- `--run` моделирует реальные тики `1/60`: код **0** исключительно при трёх победах; код **1** при проигрыше/нелегальном действии/таймауте; код **2** при заглушках base. Никогда не выводить `verified` без реальной победы.
- Требуется совместная проверка с генератором контента, общей программой волн, боссами, UI и renderer после слияния; сама по себе готовая карта не делает игру готовой.
- Визуальная приёмка: открыть `background.svg` и `thumbnail.svg` при 1366 × 768, а `preview.html` в браузере с viewport 1366 × 768. На основе аутентичной симуляции отдельно проверить направление движения у обоих мостков и читаемость башен.

**Баланс и победы: `unverified` до интеграции.**
