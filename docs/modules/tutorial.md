# Tutorial, localization and accessibility

## Public interface

`createLocale('ru' | 'en')` implements frozen `LocaleCatalog`. The same object can be passed to HUD, menus, lobby and knowledge screens. `setLanguage` changes subsequent calls; rerender the active screen when the app changes `Profile.settings.language`. `GameLocale` additionally exposes `language`, `number`, `count(unit, n)`, `wave(current, total, endless?)`, `reason(code)` and `result(commandResult)`.

`text(key, vars)` is plain text. Missing keys return the key unchanged; consumers that own legacy bilingual fallbacks can detect this. Missing variables remain visible as `{name}` rather than become `undefined`. Use DOM `textContent`, not `innerHTML`, for dynamic names/strings. Number variables use locale formatting; pass a string when already formatted. Unknown denial codes use a safe localized generic message via `reason`, not raw protocol data. Pending command results are not success. For legacy consumers, HUD `hud.credits`, `hud.owner`, `hud.invested`, `hud.sell` are labels (the HUD appends their values). Other UI labels are grouped by screen, with one bilingual row per key. HUD and lobby keys and engine/host/progression reason aliases were cross-checked against their feature branches; future keys should be added here rather than invented independently. Some screens currently own inline bilingual strings; switching them to this catalog and using `reason()` for server refusals belongs to their owners/integration.

## App integration

Create an app-owned session with `beginTutorial(profile, snapshot)` when the first solo standard Lantern Garden build phase opens. It returns null if the tutorial was seen, the map/mode is ineligible, or the run already progressed beyond the first wave. Keep the returned session only for the current run. `updateTutorial(session, profile, snapshot, events, realSeconds, action?)` returns the next session and profile; assign both, and save via the existing app save lifecycle when `tutorialSeen` changes. Do not save a stale profile over progression/settings updates. `events` is the already distributed batch of authoritative events; do not call `drainEvents` again. `realSeconds` is nonnegative elapsed wall-clock time; do not pass simulation time or multiply by speed. On a run switch discard the old session without marking it seen. For initial app resume on an eligible first build state, the tutorial may restart; contract v1 only persists the seen flag, not individual tips. Completing, skipping, reaching the 120-second limit or ending the run marks the tutorial seen; an abandoned run can start it again if not marked seen.

Mount `createTutorialPanel(root, locale, onAction)` in an app-owned non-modal HUD area that does not overlap the canvas or essential controls. `onAction` is `next` or `skip`; forward it through `updateTutorial`, then call `panel.update(session)`. Call `panel.update` on state and locale changes; `dispose()` on teardown. The panel owns only its section. It has no input lock, global keyboard handler, timers, storage, engine reference, command dispatch, currency writes or wave scheduling. Focus is not automatically moved to the panel. If the focused button disappears on completion, app should return focus to the last meaningful control. Avoid calling the app save store for every animation frame.

Sequence: place a tower, start a wave, inspect or buy an upgrade, track lives and next wave, finish. Steps advance using state or observed events; Next can bypass any step, Skip completes immediately. 120 seconds is a hard upper bound on displayed assistance, not a guarantee that the player will win or play a particular number of waves in that time. The guide is permanently accessible by calling `fieldGuide(locale)`; it returns eight stable IDs with translated title/body. No profile rewards or tutorial-only actions are created. A saved profile with `tutorialSeen=true` does not reopen it automatically.

## Accessibility acceptance checklist (practical target, not certification)

- [ ] Normal text contrast at least 4.5:1, large text at least 3:1, essential controls and visible focus at least 3:1 against adjacent colors. Check HUD, disabled explanations, tooltips, warnings and both languages on the actual backgrounds.
- [ ] Tab/Shift+Tab reach each active control in meaningful order; Enter/Space activate native buttons; Escape cancels placement; no focus trap in tutorial or help. Verify keyboard placement/selection or an equivalent accessible workflow in the integrated game, not merely keyboard navigation of menus.
- [ ] Visible focus on all actionable controls; maintain focus across reactive refresh, restore on close, do not auto-focus tips; no critical HUD controls hidden under overlays. Use a visible text/icon alongside color for status, layer and validation indicators.
- [ ] `reducedMotion` disables shakes, flashes, rapid rotation and decorative transitions; preserve state changes and readable contact indicators. Tutorial panel itself uses no animation.
- [ ] Native text at 1366×768 and 4K, 100/150/200% Windows scaling, long RU labels and EN labels, no clipped prices or keyboard focus; reflow instead of shrinking important labels. Scrollable guide must not block combat controls.
- [ ] Use native button labels and a polite live region for changing hints; no per-frame announcements. Test real keyboard and screen reader in integrated Electron. Audio must not be the only source of information.

## Verification

Run `npm run typecheck`, `npx vitest run tests/tutorial`, and `npm run check` from a complete checkout. Unit coverage uses only frozen contract and local fixtures: dictionary completeness/placeholder parity, locale switch, number formatting, Russian plural edges, known/unknown refusal codes, non-modal tutorial state and time cap, immutable game state, skip, replay isolation. Integrated HUD/menus/knowledge, real screen reader, contrast measurements and timed human playthrough remain integration acceptance tasks. The tutorial does not make claims about passability or balance.
