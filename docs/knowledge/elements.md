# Стихии — постоянные знания

`getKnowledge(): KnowledgeNode[]` возвращает 30 независимых записей контракта v1. ID `elements-01`…`elements-30`, ветвь `elements`; индексы 1–30. Каждый узел стоит одно очко и печати; следующий требует предыдущий. Иконки — относительные ключи `art/knowledge/elements/<id>.svg`, файлы в `public/`. Золотая рамка обозначает рубеж. Открытие башен по кампании не меняется.

## Семантика

Урон — `elementDamage` (только категория element); статусы — `statusDuration` (burn, poison, slow, mark, wet, reveal); щиты — `shieldDamage` (множитель урона по щиту); контроль — `controlDuration` (freeze, stun). Списки целей ограничивают ID; они не добавляют башням отсутствующие атаки или статусы. Значения — доли, складываются внутри stat. Боевые ограничения и режим iron-oath исполняет общий сервис прогресса; в этом каталоге нет начисления, изменения стоимости продажи, жизней или модификации состояния забега. В one-life ветка не меняет maxLives. Отдельного изменения темпа/дальности нет: разрешённые четыре stat этого не предусматривают.

## Суммы по целям

Четыре значения в ячейке: урон / статусы / щиты / контроль, в процентах. Это номинальные накопленные значения при наличии соответствующих механик; например, улучшение длительности яда не создаёт яд у базовой башни. Башни вне таблицы получают ноль.

Ранний профиль (5 узлов): 5 очков, 210 печатей, минимальный уровень последнего узла 1; фактически для пяти очков потребуется уровень не ниже 3. Средний (15): 15 очков, 1360 печатей, уровень не ниже 9. Полный (30): 30 очков, 6170 печатей, уровень не ниже 21. Цена указана без ранее оплаченных узлов и сбросов.

Даже без фильтра по башням суммарный расход бюджета: elementDamage 15/15%, statusDuration 15/15%, shieldDamage 19/20%, controlDuration 5/5% (вторая половина общего 10% зарезервирована другой доктрине). Каждый префикс меняет хотя бы один scoped stat до cap. Поздний узел не теряет весь эффект из-за насыщения внутри этой ветки. При интеграции проверяются остальные ветки и конечные данные башен.

## Проверка и интеграция

- `npm test -- tests/knowledge/elements.test.ts` — цепочка, цены, ограничения, прирост каждого префикса, изоляция копий и ресурсные ключи.
- `npm run check` — общая проверка после подключения независимых модулей.
- Изолированная проверка: TypeScript strict с контрактом v1; пять групп проверок Node assert на скомпилированном модуле; 30 SVG разобраны как XML и отрендерены для просмотра.
- В среде без зависимости Vitest и полного checkout эти две npm-команды не подтверждены. Тесты каталога не подменяют реальное исполнение `applyKnowledge`, combat и проверку комбинаций башен в готовой игре.
