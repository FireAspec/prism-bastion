# Портальная арка / `portal`

## Назначение

Наземная технологическая башня (26 px): 1350 кредитов, энергетический импульс 5 урона раз в 1,8 с, дальность 170. Базовая функция — прямой урон с самонаводящимся энергетическим снарядом. Это не пассивная поддержка с нулевым уроном.

Три специализации имеют разные роли:

- **A / Петля:** откат продвижения противника с индивидуальным иммунитетом; T5 — двойная арка, трёхцелевая цепная атака и способность перемотки.
- **B / Разлом:** бронепробитие, пространственные взрывы; T5 — локальная кольцевая детонация с ограниченным эхо.
- **C / Курьер:** обнаружение и ускорение собственной атаки на ранних ступенях, далее две нерекурсивные ауры для союзников; T5 — три транспортных кольца, четыре цели цепи и временная способность ускорения.

Содержательные описания каждого из 15 улучшений, цены, `StatDelta`, `replaceAttack`, статусы, эффекты и способности хранятся в `src/content/towers/portal.ts`. Это данные контракта v1: модуль не исполняет скрытые обработчики, не требует дополнительных зависимостей и не изменяет боевой движок.

## Ограничения и точная семантика

1. `portal-return` — эффект вида `portal`: `power` — пройденные назад пиксели по уже существующей полосе; `radius` — радиус выбора; `interval` — частота срабатывания; `duration` — личный иммунитет конкретного врага после попадания. При повторной покупке ступени A4/A5 эффект с тем же ID заменяется сильнейшей версией, не складывается. Возврат ограничен началом пути и сопротивлением боссов; за повторное прохождение уже оплаченного слоя денег нет.
2. `portal-courier-range` и `portal-courier-speed` — две ауры `stat:'range'` / `stat:'attackSpeed'`. C4/C5 заменяют прежние уровни по ID. Ауры не применяются к своему источнику и не образуют сеть взаимного самоусиления. Для одного stat берётся сильнейший доступный бонус, действуют общие caps поддержки (+50% скорость, +40% урон, +15% скидка). Разные `stat` совместимы. Способность overclock также не обходит cap движка.
3. Ветка B не генерирует кредиты, не даёт процента, не создаёт бесконечных ловушек. `echo` B5 создаёт максимум одну дополнительную ослабленную атаку раз в 3,4 с и ограничивает выбор четырьмя целями (`cap:4`). `pulse` наносит урон только при игровом контакте. Статусы не стакуются без ограничений.
4. `rewind` A5 активируется владельцем башни, имеет cooldown 55 с и подчиняется иммунитету к повторному контролю. В режиме `no-actives` пассивный `portal` работает, активная перемотка нет.
5. У `portal` нет функции продажи, дохода или обхода распределения слоёв. Продажа по общему правилу возвращает `floor(0.70 × invested)` только от реально оплаченных кредитов. У C5 `overclock` активен лишь когда способности разрешены. В строгих режимах эта арка остаётся боеспособной без активных способностей.
6. В области действия двух арок C их одноимённые эффекты не складываются: выбирается сильнейшая аура. На скорость самой C влияет только её покупаемый `intervalMul`; собственная аура её не ускоряет.

## Ресурсы и воспроизводимость

- `public/art/towers/portal/base.svg` и `a1..a5.svg`, `b1..b5.svg`, `c1..c5.svg` — **16 самостоятельных** 128×128 SVG, одинаковый pivot 64,64; прозрачный фон, без внешнего текста, URL, скриптов и шрифтов.
- `a1-overlay.svg`, `a2-overlay.svg`, `b1-overlay.svg`, `b2-overlay.svg`, `c1-overlay.svg`, `c2-overlay.svg` — шесть прозрачных накладок для вторичных ступеней.
- `public/art/towers/portal/preview.html` — автономная галерея всех 16 состояний и шести финальных кросс-путей; открывается локально без сети и движка. Движение из `VisualState` (`rotate` / `orbit` / `pulse`) исполняет общий renderer; статический SVG не симулирует физику/урон.
- `tests/towers/portal.test.ts` — fixture resolver проверяет все 64 легальных tier-вектора, визуальный выбор и шесть финальных комбинаций, конечность всех чисел, ID/стоимость, отсутствие дублирования эффектов, файловую комплектность и независимость копий.

## Интеграционная граница

При импорте `getTower()` возвращает новую структуру. Прямые зависимости только от неизменного `src/contracts/index.ts`. Каталог на исходном commit пока не вызывает этот модуль автоматически, боевой модуль на базовой ветке остаётся заглушкой; локальные тесты проверяют данные и работу отдельного fixture resolver, **но не являются боевым прогоном реальной симуляции**. Визуальный просмотр SVG и всех шести композиций проведён посредством локального растрирования, не в игровом renderer. Подключение к общему `resolveTower`/боевой сцене выполняет владелец интеграции после слияния, без изменения этого контракта.
