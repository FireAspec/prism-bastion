# Небесная мортира (`mortar`)

Модуль контента для Prism Bastion, контракт v1. Файл данных: `src/content/towers/mortar.ts`, экспорт `getTower(): TowerDef`; каждый вызов возвращает независимую глубокую копию. Ни движок, ни боевой модуль, ни общий контракт здесь не изменяются.

## Основа и ограничения

| Параметр | Значение |
|---|---:|
| Стоимость, normal | 800 кредитов |
| Категория и местность | `tech`, `land` |
| Размер для размещения | 26 пикселей |
| Базовый урон | 50 kinetic |
| Интервал | 2,4 с |
| Дальность | 340 пкс |
| Взрыв / выстрелы за залп | 44 пкс / 1 |
| Скорость / радиус снаряда | 320 пкс/с / 5 пкс |
| Подготовка / угол навесного выстрела | 0,24 с / 65° |

`mode: mortar` использует отложенный контакт с заданной точкой, после которого наносится splash-урон по фактической области поражения. `count` — число независимых снарядов за один залп; в ветке B они могут ударить по разным целям, в ветке A — создать несколько широких зон. Ни одна ветка не использует `replaceAttack`, поэтому ранние улучшения второй ветки не уничтожают основную специализацию. Присутствуют только поля frozen DSL: `delta`, `addStatuses`, `effects`, `abilities`, `visual`.

Дальнейшее усиление одной характеристики никогда не отменяет ранее купленные эффекты. Метка C5 заменяет C2 с тем же `kind`, с увеличенной длительностью; аура C5 заменяет C3 по одинаковому ID `mortar-signal-net`, а не удваивает радиус. Эффект `slow` ограничен общими правилами минимальной скорости, `burn` — лимитом стеков. Повторное попадание обновляет длительность, не создавая бесконечный контроль.

## Численный срез баланса

**Условный одноконтактный DPS:** `damage × count / interval`. Это верхняя оценка прямого урона залпа, если *каждый* снаряд попал по одной выбранной цели, без брони/сопротивлений/щитов, промахов, расстояния полёта, горения, активных способностей, повторных попаданий по толпе и положительных эффектов союзников. Это не измерение в симуляции и не доказательство проходимости. **Накопленная цена** включает башню за 800 и префикс одной выбранной ветки.

Для B высокая численная оценка компенсируется меньшим взрывом и распределением снарядов по целям. Для A огромный радиус повышает охват плотных волн; пересекающиеся зоны не означают гарантированное многократное попадание в каждого врага. Для C базовая роль — раскрытие скрытых врагов через `detects/reveal/mark`, а не доход. Все три пути пригодны как вторичные T1–T2: A даёт взрыв/бронепробитие; B — второй снаряд и темп; C — обнаружение и метку.

## Визуальные ресурсы

`public/art/towers/mortar/` содержит:

- 16 полных видов, `base.svg`, `a1.svg`…`a5.svg`, `b1.svg`…`b5.svg`, `c1.svg`…`c5.svg`;
- 6 прозрачных накладок `a1-overlay.svg`, `a2-overlay.svg`, `b1-overlay.svg`, `b2-overlay.svg`, `c1-overlay.svg`, `c2-overlay.svg`;

У всех SVG `viewBox="0 0 128 128"`, единая позиция платформы, прозрачный фон, отсутствуют внешние URL/шрифты/скрипты. A5 — гигантский наклонный ствол на реактивной опоре; B5 — четыре коротких ствола с пересекающимися трассами; C5 — сигнальная чаша с тремя парашютными светильниками. Накладки входят только в периферийное пространство и не меняют T5-основу.

## Совместимость и независимая приёмка

Стандартные правила `legalTiers`/`canUpgrade` запрещают три ветки или две ветки выше T2. Приложение должно брать основную SVG из самого высокого ненулевого пути и наложение вторичной ветки через поле `ResolvedTower.secondaryOverlay`, используя таблицу выше. Ресурсы SVG — готовые изображения; `muzzle`/`projectile`/`impact` в `VisualState` — именованные визуальные сигналы для процедурных эффектов рендера.

Проверки:

```sh
npm run typecheck
npm test -- tests/towers/mortar.test.ts
npm run check
```

Тесты модуля проверяют точную арифметику цен, независимость копий, все допустимые тройки tiers локальным *fixture resolver*, отсутствие нечисловых параметров, шесть T5-кросс-путей, изменение механики T5, все SVG и локальную галерею. Для реального игрового `resolveTower`, контакта снарядов и поведения способностей нужен `src/combat/index.ts`, который в базовом commit ещё является заглушкой. Нельзя считать эти будущие интеграционные проверки выполненными. Реальная оценка баланса по боевым волнам и воспроизводимые campaign replay также остаются за интегратором. Все статусы и способности закодированы v1 DSL без расширения контракта.

Обычную цену продажи рассчитывает **только движок** из фактически потраченного через `floor(0.70 × invested)`; модуль не добавляет никаких доходных или ценовых эффектов.
