# Бастионная пушка (`cannon`)

## Назначение и подключение

Начальная наземная боевая постройка. Входная точка `src/content/towers/cannon.ts` экспортирует `getTower(): TowerDef`; каждый вызов возвращает независимую глубокую копию. Контракт v1 не изменён.

| Параметр базы | Значение |
|---|---:|
| Стоимость на normal | 550 |
| Урон / интервал / дальность | 30 / 1,7 с / 170 px |
| Начальный DPS без защиты | 17,65 |
| Режим / стихия | `shot` / `kinetic` |
| Выстрелов / уникальных прямых целей | 1 / 1 |
| Скорость / радиус ядра | 410 px/с / 5 px |
| Время подготовки / размер установки | 0,14 с / 26 px |
| Размещение / категория | `land` / `weapon` |

### Порядок разрешения улучшений

1. Базовый `AttackDef` (отдельная копия).
2. Если основной путь достиг T3/T5, его последний `replaceAttack`; ни одно улучшение T1/T2 не подменяет атаку.
3. Все `delta` приобретаемых ступеней A → B → C, по возрастанию тира (умножения/прибавления к выбранной основе).
4. Основной полноразмерный SVG — наивысшая ступень основного пути; при равных ненулевых тирах меньший индекс A/B/C. Второй путь T1/T2 добавляет поверх него `${path}${tier}-overlay.svg`.

Движок читает поля по контракту, а не по отображаемой форме рисунка. `getTower()` не вычисляет завершённую атаку и не выполняет симуляцию.

Шоковый статус задаётся `StatusSpec(kind='stun',power=1,duration=...)`. `shred.power` предназначен для вычета соответствующего количества брони с нижней границей 0. Если единица мощности `shred` или конусная геометрия потребуют иной интерпретации в будущем универсальном боевом модуле, это следует зафиксировать единообразно для всех башен в боевом модуле — локальных исключений для пушки нет. Художественный шестигранный импульс C5 использует **круглую игровую область `splash`**, поскольку отдельной формы «hex hitbox» в контракте нет.

## Вложенная стоимость и теоретическая эффективность

Показатель DPS — `damage × count / interval` для базовой атаки и всех `delta`. Для B он означает **потенциал по совокупности зарядов**, а не обещание попадания всех зарядов в одного врага. Для A/C показатель приведён **без дополнительных целей взрыва**, брони/резистов/щита, бонуса босса, попадания снаряда, времени полёта и перезарядки. Реальный результат зависит от траектории и распределения врагов. Доходных эффектов нет.

Остальные важные различия:

- A5: урон по боссам ×2,1142 за счёт A2/A3/A4/A5. В A5/C2 дополнительно ×1,05 от C1 и урон по щитам ×1,18. В A5/B2 прямое пробитие +1, дальность 212,636 px.
- B5/A2: дальность 205,1312 px (`164 × 1,06 × 1,18`), урон по боссам ×1,10. B5/C2: бронепробитие +5, щиты ×1,18. Каждое попадание может затронуть максимум `pierce` уникальных прямых целей; один снаряд не повреждает одну и ту же цель многократно из-за кадров.
- C5/A2: дальность 200,6 px; прямое бронепробитие +9 и дополнительный множитель по боссам. C5/B2: 2 прямые цели на заряд, скорость снаряда ×1,12, дальность 180,2 px.
- C3–C5 не создают постоянного оглушения: интервал минимум 1,8/2,15 с и длительность максимум 0,32 с; боевые правила отдельно ограничивают цепное оглушение и устойчивость боссов. Отталкивание ограничено правилом личного cooldown.
- Скидки режима/знаний меняют реально оплаченный `invested`, но не числа в таблице. Возврат строго `floor(0,7 × invested)`; бонуса продажи, добычи, ауры, способности, бесплатных объектов нет.

## Художественная система

Файлы `public/art/towers/cannon/base.svg`, `a1..a5.svg`, `b1..b5.svg`, `c1..c5.svg` — **16 самостоятельных полноцветных SVG 128×128**, а `a1-overlay.svg`/`a2-overlay.svg` и соответствующие B/C — **6 прозрачных накладок**. Не требуют внешних URL, изображений или скриптов. Ключи `VisualState` назначены для muzzle/projectile/impact/motion/glow, что позволяет общему рендереру визуализировать вылет и контакт по настоящему событию симуляции.

- A1/A2 усиливают ствол/станок, A3/A4 добавляют камеру и гидравлические опоры, A5 — два полноразмерных ствола и раздвижной лафет.
- B1/B2 добавляют разделитель и механизм подачи, B3/B4 увеличивают веер до трёх/пяти стволов, B5 — семь коротких стволов, обойма и отдельные медные осколки.
- C1/C2 вводят бронештырь и магнитные крылья, C3/C4 — разрядный шестиугольник и катушки, C5 — подвешенное ядро, шесть электромагнитов и двойной шестигранный контур.

`public/art/towers/cannon/preview.html` открывается локально без сервера и показывает 16 моделей, все шесть готовых кросс-форм 5–2–0 с соответствующей накладкой T2 и все шесть накладок отдельно. Все модели сохраняют центр 64×64 и тот же игровой footprint 26, независимо от визуального размера.

## Проверки и ограничения интеграции

В базовом коммите `65ae156` `src/combat/index.ts` и `src/content/index.ts` являются заглушками. Поэтому проверены данные и независимый тестовый resolver по опубликованному правилу; боевой replay с настоящим врагом пока **не проведён** и не заявляется. При интеграции требуется в действующем движке подтвердить поведение `cone`, поражение `splash`, приоритет `replaceAttack`, ослабление stun на боссах, `shred`, отталкивание и распределение `count`.

Приёмка этого модуля: `npm run check` (TypeScript strict, Vitest, Vite), перечисление всех 216 комбинаций с 64 легальными, все шесть финальных 5–2–0, расчёт характеристик и вложенных цен, проверка наличия всех 22 SVG и HTML. SVG дополнительно экспортированы Inkscape в PNG; визуально осмотрены контактные листы основной линейки и шести кросс-путей. Это просмотр статического искусства, **не** проверка игрового рендера или анимаций при 1×/3×. Полный боевой QA и балансовые replay остаются задачами общей интеграции.
