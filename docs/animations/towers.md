# Tower motion (v1)

`createTowerMotion()` implements frozen `EntityMotion` and adds two optional diagnostics: `retired()` (short-lived sale draw records) and `trackedCount()` (live and retiring records). It never mutates the game snapshot, spends credits, advances projectiles or emits game events.

## Renderer adapter

Create one instance per run. On each authoritative event/snapshot packet call `consume(events, state)` once, then `update(realSeconds, state)` once per render frame. For each live tower, draw its resolved main SVG and secondary overlay with `sample(tower.id)`. `offset` is world pixels, `rotation` is radians, `scale` multiplies the resolved visual scale, `opacity` and `glow` are normalized. The confirmed attack direction uses world +X as angle zero. Apply the same transform to the corresponding art; author-facing barrel offsets must account for the SVG's actual intrinsic orientation. Use the event or projectile/strike world coordinates for muzzle, path and hit; never transform physics by recoil. At a launch tick offset is zero and scale is 1. Idle movements are deliberately small.

Draw `ghostAsset` only in the same footprint and transform as the current main model, with `ghostOpacity`; never draw an additional physical entity or a full opaque new model underneath an old one. For `retired()` draw the returned last model in the saved location, only if it no longer exists in the snapshot. No selection, range, collision or attack visuals attach to retired records. On asset load error skip the ghost, retain the current model, and use the renderer's normal missing-current-asset fallback. The module does not perform network fetches; asset names are local canonical paths. `towerAsset` and `towerOverlay` are convenience functions matching the frozen main path tie-break and legal cross path rules. The actual content's resolved visual remains the renderer's source of truth. The gallery explicitly handles image load failure.

A local command with `pending` does not call `consume`; placement preview remains `RenderOverlay.placement`. Successful confirmation must carry `place`, `upgrade`, `sell` or `ability`; merely observing a new entity after reconnect does not replay its construction. Event IDs are assumed globally increasing within a run, sorted per batch; repeated IDs are ignored. New run ID or decreasing tick clears state. A snapshot with no tower and no sale event removes its entry immediately. A sale event requires the previous entity to have been observed, otherwise no location/model can be recovered safely.

Construction/upgrade/sale follow real elapsed presentation time, including the build phase. Combat pulses and idle use authoritative `state.time`, so pause freezes them and 3× advances them with the simulation. `setReducedMotion(true)` suppresses recoil, breathing, rotation oscillation, glow and transition ghost; aim itself remains available. The event clock is never used to infer damage. The short T5 reveal is bounded to 0.95 s and approximately 11% extra scale, avoiding screen-wide effects.

## Gallery and tests

Run `npm run dev` and open `/tests/animations/towers/gallery.html`. Select each of 30 towers and 22 cases (base, 15 transitions, six final cross paths). The same implementation supplies actual transform samples. Controls replay placement/upgrade, trigger a shot, strike, ability and sale, switch 1×/3×, cap the simulated presentation FPS at 30/60/120 and toggle reduced motion. The preview uses canonical SVGs directly, no replacement art; missing files show an explicit error. The gallery is an isolated render harness, not a combat simulation.

Run `npx vitest run tests/animations/towers/motion.test.mjs`, then `npm run check`. Tests cover 30 bases, 450 sequential upgrades, 90 T5 reveals, 180 cross-path asset mappings, event deduplication, interruptions, reduced motion, projectile/strike pose, 60 towers across 200 cycles, invalid asset names and frame pacing.

## Boundary and integration notes

Frozen MotionSample has a single whole-model transform and a single previous asset; it cannot independently articulate individual barrel/ring/tree parts, layer multiple interrupted ghosts, or express an independently animated secondary overlay or particles. Mechanism-specific motion profiles distinguish those categories through bounded whole-model rotation, breathing, bob, recoil and glow. Individual SVG internals, exact muzzle socket positions and layered secondary transition art require renderer-side support or a future optional per-part transform interface. Idle aim is held from the most recent confirmed attack or strike state: the frozen tower snapshot does not expose a live aim target, so this does not anticipate a future shot. Melee windup follows the authoritative StrikeState and contact event. When the host batches several upgrades between snapshots, fromVisual/toVisual can preserve the most recent reveal; the intermediate state is not reconstructed by inventing unconfirmed tiers.

The base commit has renderer and tower content stubs and lacks the checked needle base SVG. The independent test suite can run against the embedded contract, but actual art orientation, true integrated muzzle socket alignment and live 30-tower gallery visual acceptance must be verified after content and renderer integration. No claim of integrated visual approval is made.
